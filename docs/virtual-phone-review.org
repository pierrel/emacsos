#+title: Virtual phone acceptance and review record

* Current revision

The shared-runtime revision requires fresh seven-scenario UI acceptance from
clean source in both the isolated candidate and an explicit composition with
current deployed application code. No previous result substitutes for that run.
The published procedure is [[file:../deploy/virtual-phone/README.md][the virtual phone workflow]]. Capture screenshots and
logs in private state outside Git, and record exact source identities with the
results. Screenshots are deliberately excluded from this branch and its history.

The first revised integrated path built the shared physical payload, booted
Alpine/OpenRC, passed the physical session's Sway-window and Emacs-server
readiness probes, and produced a real 720x1440 capture. Guest diagnostics imported
D-Bus, Requests and PyYAML. This development check is not final acceptance.

* Known boundaries

The guest has no external network, real credentials, personal history, modem,
sensors or battery. Assist is unavailable by design; real isolated Assist
integration remains roadmap work. Physical behavior is not established by guest
UI success. Mobile Firefox policy uses the native signed postmarketOS v25.06 package,
4.6.0-r0, via a one-off tagged repository. It matches the recorded physical
package input; no current physical package-version check is claimed. The guest has an unresolved historical SSH I/O-error observation;
no long-lived reliability guarantee follows from short acceptance sessions.

Physical shared deployment changes require source review and deterministic
checks. No physical deployment or merge is authorized by virtual acceptance.
