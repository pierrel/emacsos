#+title: SMS snapshot identity amendment
#+date: 2026-09-16

* Correction

An unmatched outgoing modem snapshot may attach only when exactly one matching
local =sending= or =sent= record exists, and that local record has no modem path.
The two states form one candidate set: state preference cannot disambiguate
identical sends.  An already attached local record is reconciled only through
its same-path branch, so a later identical modem object cannot replace its
identity.

An active refresh owns same-owner/generation live snapshots until its list and
snapshot transaction settles.  A live snapshot already completed when the list
arrives is routed through the refresh cutoff when listed, or applied live after
the transaction when absent.  A delayed Added event for a retained listed path
marks that result unread without starting a second reader.  This barrier keeps
both pre-list and post-child-completion ordering from mutating state outside the
refresh transaction.  A promoted incoming snapshot retains its unread meaning
when the transaction applies it.  With no active refresh, a live job still
applies immediately.

* Verification

ERT covers distinct B-then-A modem objects with identical message content,
ambiguous pathless local =sent= and =sending= records, a post-cutoff local send
whose refresh job is promoted live, and unread preservation for a coalesced
incoming Added event.  It also covers live completion before list resolution,
a delayed Added event after one listed child completes while another remains,
and a live path absent from the eventual list.
