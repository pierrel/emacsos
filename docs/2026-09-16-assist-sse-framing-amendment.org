#+title: Assist SSE framing and accounting amendment
#+date: 2026-09-16

* Correction

The Assist Web stream guard treats bytes delivered to the process filter as
raw HTTP transport.  It bounds each raw callback to 1 MiB and forwards it
unchanged to =url-http=; it does not interpret HTTP headers, chunk framing, or
line endings as SSE records.

Only after =url-http= decodes the response does the event reader copy committed
entity bytes into a private parser buffer and apply the 64 KiB
complete-or-unfinished SSE record bound.  For a chunked response, the stock
decoder's current chunk start and declared length define that committed range;
the parser never sees a chunk terminator or incomplete chunk header.  The
response buffer remains owned by =url-http=, and pruning preserves its active
chunk.  The parser accepts both LF and CRLF SSE record delimiters and removes
either delimiter before dispatching the same status, delta, error, or terminal
event.

* Verification

ERT drives the stock =url-http= filter with a chunk-framed HTTP/1.1 response
whose decoded SSE record uses CRLF and spans two transport chunks.  The first
chunk's raw terminator cannot complete the partial SSE record; the second chunk
dispatches the status exactly once.  Separate coverage proves a single
oversized raw callback is rejected without treating its contents as SSE, a
decoded CRLF record is parsed directly, and hot reload discards legacy raw-byte
accounting while retaining the decoded tail.
