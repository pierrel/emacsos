#+date: 2026-09-20

* Diagnostic checkpoint

This is a non-candidate recovery checkpoint.  It preserves an attempted D5
queue-controller implementation for later diagnosis; it does not amend or
supersede the accepted concurrent-request design.

The original recovery failure was load ordering: the controller definitions
were accidentally nested in canonical-adoption code, leaving the legacy
=emacsos-assist-web-send= effective.  Closing that function at its boundary
made the controller load.  The existing-canonical adoption regression then
exposed a second concrete defect: the source draft assigned its returned thread
id before looking up another canonical owner, so it matched itself and skipped
adoption.  Looking up the owner first makes
=test-assist-web-new-thread-acceptance-adopts-an-existing-canonical-buffer=
pass.

The enabled controller is not compatible with the existing singleton/cache and
render contracts.  =make test-elisp= reports 590 expected results of 622, with
32 unexpected results: one unrelated call test and 31 Assist Web failures.
Representative in-scope failures cover draft-save ordering, cache-failure
recovery, restore normalization, presentation/history preservation, retry and
stale-callback handling, and canonical transfer persistence.  No candidate,
deployment, merge, or integration claim follows from this checkpoint.
