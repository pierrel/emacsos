#+title: Wi-Fi wrong-password retry amendment
#+date: 2026-09-15

* Historical supersessions

This amendment replaces the failed secured-join behavior and the helper-output
description in [[file:2026-09-12-wifi-network-access.org][Wi-Fi network access]], Credential and privilege boundary.  That
record remains the historical design for the rest of the feature.

* Correction

Each first-seen secured join gives NetworkManager a fresh, helper-owned profile
name.  If NetworkManager rejects the join, the helper resolves that name to one
canonical UUID and deletes only that exact profile.  NetworkManager's explicit
not-found result proves that no matching profile remains at lookup time.  Any
other failed, timed-out, or ambiguous lookup, or a failed or timed-out deletion,
reports the controls as unavailable instead of claiming a retry-safe failure.
Termination kills an active connection child, defers exit through the bounded
cleanup, and leaves cleanup children alone to reach that bounded result.
Publication remains cancellable until the UUID marker advances to an idle
generation.  If a signal races with the profile rename, the helper deletes that
exact UUID even when the rename already took effect, so the failed publication
cannot become visible as saved.

After a failed or cancelled attempt, its ownership record deliberately remains
pending even when the bounded deletion succeeds.  The next credentialed join
reconciles that exact record before atomically replacing it with the new
attempt.  Thus power loss cannot make deletion durability race ahead of the
ownership record and expose a profile that NetworkManager restores on reboot.

The helper records its randomly selected, previously unused attempt name in one
durable, root-owned marker under =/var/lib= before asking NetworkManager to
connect.  Once the attempt has a canonical UUID, the helper atomically replaces
the name marker with that UUID.  Atomic replacement includes file and directory
syncs, so a reboot or power loss cannot discard ownership while leaving the
NetworkManager profile behind.  Each transition to idle advances a monotonic
generation.  The status reader accepts its saved-profile enumeration only when
the complete marker record is identical before and after that enumeration.
Therefore an attempt that begins, changes ownership form, or finishes during a
read makes the whole saved snapshot inert rather than publishing stale state.

The status reader hides only the profile owned by the stable marker.  UUID
ownership needs no editable-name lookup.  While name ownership survives, the
reader uses an exact editable-name lookup only to exclude that pending profile;
emitted saved profiles are still identified solely by UUID and actual SSID.
The helper uses the same exact name during its next reconciliation.  A
pre-existing profile whose editable name resembles an attempt remains an
ordinary saved profile.  A failed, interrupted, or incompletely reconciled
attempt therefore cannot be exposed as saved once status reads work again.
While NetworkManager itself is unavailable, the existing fail-closed reader
keeps connection rows inert rather than claiming an immediate retry is possible.

Before each secured join, the helper removes the exact UUID or uniquely named
profile recorded by a surviving marker.  It selects a different random name if
that name identifies one existing profile; an ambiguous or malformed lookup
fails closed.  It then atomically replaces the old ownership record.  This
prevents NetworkManager's matching-profile behavior from reusing an earlier
failed attempt instead of creating the freshly named one.
The helper's lock is inherited by every NetworkManager child, so a force-killed
helper cannot admit another mutation while an orphaned child is still running.

This keeps a wrong password from turning the next refreshed row into a saved
connection that bypasses the password prompt.  The password remains stdin-only;
the helper-generated profile name and resolved UUID contain no credential.
The credential-bearing connection command still discards its output.  Exact
name reconciliation instead reads only the UUID lookup's noncredential output,
with the same three-second deadline as the lookup and a 4096-byte accumulation
limit; timeout or the first excess byte kills and reaps the lookup process group
and fails closed.

Deterministic coverage makes a failed =nmcli --ask= invocation create a profile,
requires its exact UUID deletion, and then proves a new secured attempt invokes
the credential path again and succeeds.  It also reconstructs a pending marker
after a reboot boundary and changes the marker generation during saved-profile
enumeration, requiring exact recovery and a rejected stale snapshot.
