#+title: Wi-Fi wrong-password retry amendment
#+date: 2026-09-15

* Historical supersessions

This amendment replaces only the failed secured-join behavior implied by
[[file:2026-09-12-wifi-network-access.org][Wi-Fi network access]], Credential and privilege boundary.  That record remains
the historical design for the rest of the feature.

* Correction

Each first-seen secured join gives NetworkManager a fresh, helper-owned profile
name.  If NetworkManager rejects the join, the helper resolves that name to one
canonical UUID and deletes only that exact profile.  NetworkManager's explicit
not-found result proves that no matching profile remains at lookup time.  Any
other failed, timed-out, or ambiguous lookup, or a failed or timed-out deletion,
reports the controls as unavailable instead of claiming a retry-safe failure.
Termination kills an active connection child, defers exit through the bounded
cleanup, and leaves cleanup children alone to reach that bounded result.

The =emacsos-wifi-attempt-= name prefix is an internal pending-profile namespace.
The status reader never exposes a profile in that namespace as saved.  A
complete pending name is longer than the maximum valid SSID, so publishing a
successful join by renaming its exact UUID to the SSID cannot collide with the
namespace.  A failed, interrupted, or incompletely reconciled attempt therefore
cannot be exposed as saved once status reads work again.  While NetworkManager
itself is unavailable, the existing fail-closed reader keeps connection rows
inert rather than claiming an immediate retry is possible.

Before each secured join, the helper removes every exact UUID still carrying an
internal pending name.  This prevents NetworkManager's matching-profile behavior
from reusing an earlier failed attempt instead of creating the freshly named one.
An unexpectedly oversized pending set fails closed instead of constructing an
unbounded privileged command.
The helper's lock is inherited by every NetworkManager child, so a force-killed
helper cannot admit another mutation while an orphaned child is still running.

This keeps a wrong password from turning the next refreshed row into a saved
connection that bypasses the password prompt.  The password remains stdin-only;
the helper-generated profile name and resolved UUID contain no credential.

Deterministic coverage makes a failed =nmcli --ask= invocation create a profile,
requires its exact UUID deletion, and then proves a new secured attempt invokes
the credential path again and succeeds.
