#+title: Assist Web adoption durability correction
#+date: 2026-09-22

* Correction

Canonical adoption saves the complete destination recovery record while the
source record remains durable, then retires the source.  A failed retirement
restores the destination's prior record when possible; a failed restoration
leaves recoverable duplicate records rather than losing the accepted Run.
The retained source records the canonical thread id while keeping its
=new-thread= cache name, so rollback and reload use an exact Run GET rather
than a second POST.  When both records survive a restart, the live canonical
buffer deduplicates the immutable key and Run before transport resumes.
