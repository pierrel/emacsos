#+TITLE: Wait for guarded input before the initial supervisor wake
#+DATE: 2026-10-12

* Startup correction

Copilot R3 on =328e4d7= found a real startup race. The asynchronous worker opens
its FIFO only after trusted input registration and permanent privilege drop,
but the initial =wake= changed the display before its eventual transition write
blocked on that FIFO. That handshake was too late to establish registration
before the supervisor's initial =session-power wake=. A power/ring input during setup could be
lost. The fix opens the existing FIFO for writing, with a bounded timeout,
before invoking initial wake. The open releases only after the monitor reader
exists. No new readiness file, event type, actor or ownership mechanism is added.
Missing readiness fails startup within the bound before that initial wake.
Sway and Emacs already run earlier in startup; this barrier precedes the
supervisor's explicit power action, not all display activity during boot.
The worker's comment now describes this pre-wake barrier.

A deterministic test executes the actual contiguous startup block from
=openrc-session=. Narrow process-group/power fixtures pause monitor setup before
its FIFO reader opens. The unchanged =328e4d7= block fails with =initial display
changed before monitor registration=. The successor must show no display action
while setup is paused, then finish successfully after release. A second case
never releases setup: startup must fail within five seconds and must not change
the display. The fixture owns and closes its process group, including children
after parent exit. This test does not claim a full UI boot or physical event.
