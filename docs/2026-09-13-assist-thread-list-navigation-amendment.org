#+title: Assist thread navigation clarification
#+date: 2026-09-13

* Confirmed-empty new-thread choices

A new-thread request keeps one pending intent while a usable repository and
harness pair is unavailable, whether the catalog is absent or a stale catalog
lacks one of those choice sets, and the shared asynchronous refresh is
resolving them.  Repeated requests still coalesce into that one intent.  A
cached catalog that contains both choice sets opens the chooser immediately
while its refresh proceeds.

When a current validated catalog confirms that repositories or harnesses are
empty, the client clears the pending intent and reports that no choices are
available without opening a chooser.  A later catalog refresh cannot
unexpectedly resume that request.  Refresh failure likewise clears the intent
under the existing failure policy; retaining it applies only while unavailable
or stale choices are actively being resolved.

* Conditional thread navigation

The global =C-c C-a t= binding remains available from every buffer.  It opens
the catalog completion chooser when the catalog contains threads.  When the
catalog contains no threads, including before a usable catalog has loaded, it
opens the native thread list instead so loading, empty, and failure state stay
visible.  The persistent =Threads= modeline control always opens that native
list.
