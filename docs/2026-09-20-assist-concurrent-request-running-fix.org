* Design

Each canonical thread buffer keeps an ordered, durable two-resident normal
queue: its active or recoverable request and one follow-up.  Buffers admit
independently.  A buffer serializes POST acknowledgements and observes one Run
at a time, so a same-thread follow-up cannot overtake an uncertain predecessor.
The local =*chat*= transport remains exclusive: the shared activity state is
=chat=, =web=, or nil.  =web= is aggregate activity rather than a selected
buffer owner, so canonical SEND stays available while any web Run is active.

The completed correction must give every resident record its immutable
idempotency key, submitted text, accepted Run identity, state, and rendering
markers.  The accepted D5 state table covers queued, posting,
acceptance-unknown, retryable and permanent rejection, identity conflict,
accepted-unobserved, observing, terminal, reconciling, and pre-canonical
recovered-head states.  It requires persist-before-network transitions,
exact-Run recovery, bounded request and cache data, destination-owned
new-thread adoption, and no text-based identity matching.  Errors use fixed
local wording and never include draft text or credentials.

* Verification contract

Regression coverage exercises public Send and Refresh with withheld/reversed
callbacks: a same-thread follow-up, a separate-thread submission, admission
barriers, retry/rejection classification, restore normalization, pre-canonical
recovery/adoption, stale callback isolation, request-budget cleanup, abort and
SEND touch affordances, aggregate activity, deployed bindings, and manifest
integrity.  The full ERT suite and the PinePhone OpenRC deployment checks are
required before the candidate is reviewable.
