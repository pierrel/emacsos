*Living doc.* Unlike the dated design docs in this directory, this one is
a running build log for the *physical* device — the bill of materials,
what's connected, how it's held together, and what's still unknown. Edit
it as you build; append dated notes under [[*Iteration log][Iteration log]] so the history of

Goal of the current milestone: take the existing bench rig *outside* and
field-test it one-handed, *without a real case*. Everything below is
scoped to that.

* What this device is
A malleable Emacs handheld — a 320x240 touchscreen frame with a nine-key
(T9) keyboard, on a Raspberry Pi, talking over a tunnel to the =assist=
agent at home. See [[file:../README.org][README.org]] and the manifesto post
"Where we are now" on larochelle.io for the why. This doc is only the
*hardware*.

* Assembly: the slab (no case)
Don't enclose anything. Mount everything to *one rigid flat plate* and
hold the plate like a phone. The plate does the structural job a case
would, with zero design time.

** Layout
- *Substrate:* an acrylic experiment base plate (grid of holes, [[https://www.cytron.io/p-rpi-acrylic-experiment-base-plate][photo]]) is
  the easy buy; bare 3mm acrylic / FR4 protoboard / thin plywood also work
  (foamcore is fine for the very first walk). Cut/pick slightly bigger than
  the screen.
- *Front — boards:* Pi + display HAT are already a GPIO sandwich; make it
  rigid with M2.5 nylon standoffs + screws through the mounting holes.
  The SIM7600 connects by *USB, not the header*, so it doesn't stack —
  standoff or VHB-tape it to a free corner.
- *Back — power:* Velcro the cell + the two power boards (PowerBoost,
  modem boost) and the modem if not standoff'd, so you can pull the cell to
  swap/recharge. Velcro over tape: repositionable, survives many test cycles.

** The two joints that actually break
Everything else is cosmetic. These two will kill a field test if not
strain-relieved:
1. *Modem USB-OTG micro joint.* A micro-USB plug cantilevered off the Pi
   snaps / intermittently disconnects under hand flex. Anchor the cable
   to the plate (zip-tie + adhesive mount, or hot glue) ~1" back from the
   connector so movement pulls on the plate, not the plug. Shortest OTG
   cable possible.
2. *Antenna u.FL/IPEX connector.* Rated for only a handful of mating
   cycles; tears off if the pigtail flops. Tape the pigtail down *at the
   connector*, route to the *top edge*, let only the radiating element
   hang free. Don't coil it against the boards (detunes it).

** Fastest viable build (one evening, ~$15 consumables on top of the BOM)
1. Cut a backing plate.
2. Standoff the Pi+screen sandwich to the front.
3. Velcro the cell + power boards + modem to the back/corner.
4. Strain-relief the OTG plug *and* the antenna pigtail.
5. Antenna whip out the top edge, taped at the root.
When the connectors prove they survive a few outings, *then* it's worth a
printed case.

* Power & wiring
The rule that trips people up: *two power rails, one data link.* The Pi
and the modem are powered separately; they're only joined by a USB data
cable. Never try to power the modem *through* the Pi — the Zero 2 W
can't source the SIM7600's transmit-burst current, and you'll get
brownouts / dropped registration exactly when the radio keys up.

The design: *one shared cell, two independent 5 V converters, an I²C
gauge the Pi reads.* Sharing the *cell* is fine — it's only the *5 V
rails* that must stay separate so the modem's transmit bursts don't sag
the Pi.

#+begin_example
                       ANTENNA (u.FL whip → top edge)
                              │
   ┌──────────────────┐   data only (USB-OTG, short)   ┌──────────────────┐
   │  Pi Zero 2 W     │ ◄═══════════════════════════►  │  SIM7600G-H HAT  │
   │ [320x240 screen] │  Pi inner micro-USB (HOST)     │ (qmi_wwan→wwan0) │
   └─┬──────────┬─────┘                                └─────────┬────────┘
     │ I²C      │ 5V PWR IN (outer micro-USB)            5V PWR IN│ (≥3 A)
     │          │ ▲  RAIL 1                              RAIL 2 ▲ │
     ▼          │ │                                             │ │
 ┌────────┐  ┌──┴─┴──────────┐                         ┌────────┴─┴──────┐
 │MAX17048│  │ PowerBoost    │                         │ 5 V/3 A boost   │
 │ gauge  │  │ 1000C         │                         │ board           │
 └───┬────┘  │ (charge+boost)│                         └────────┬────────┘
     │       └──────┬────────┘                                  │
     │   taps cell  │  ▲ wall recharge (micro-USB IN)  taps cell│
     └──────────────┴──┴──────────────────────────────────────-┘
                       │
                       ▼
               ┌──────────────┐
               │ Li-ion cell  │  one shared cell (or a parallel 18650 pack)
               └──────────────┘
#+end_example

- *RAIL 1 → Pi.* A PowerBoost 1000C boosts the shared cell to 5 V into the
  Pi's *outer* micro-USB (=PWR IN=), and is also the *charger* — wall
  recharge goes into the PowerBoost's micro-USB IN, same as the bench rig.
- *RAIL 2 → modem.* A *bare 5 V/3 A boost board* taps the *same cell* and
  feeds the SIM7600's own power input. A single PowerBoost (~2 A peak) is
  too weak for the radio's ≥3 A bursts, which is why the modem gets its own
  3 A boost rather than a second PowerBoost. *Do not* bus-power the modem
  off the Pi.
- *Battery % → Pi → Emacs.* The *MAX17048* fuel gauge sits across the
  *raw cell* (3.0–4.2 V, *not* a 5 V rail) and talks I²C to the Pi —
  =SDA=→GPIO2, =SCL=→GPIO3, =3V3=, =GND= (enable with =dtparam=i2c_arm=on=).
  The Pi reads state-of-charge and shows it in Emacs; no separate screen.
  One gauge, one cell: the MAX17048 is single-cell with a *fixed* I²C
  address (0x36), so keep one shared cell (or a parallel 18650 pack = one
  logical cell). This is the [[file:../roadmap.org][roadmap]] fuel-gauge item, now load-bearing.
- *Data link.* Pi's *inner* micro-USB (the USB *host* port, enabled by
  =dtoverlay=dwc2,dr_mode=host= + =otg_mode=1= in =/boot/firmware/config.txt=,
  per [[file:2026-05-26-cellular-data-connectivity.org][cellular doc]] ~l.289) → SIM7600 data port, via the *shortest*
  USB-OTG cable you have. This is joint #1 from [[*The two joints that actually break][above]] — strain-relieve it.
- *Antenna* off the SIM7600's u.FL, routed to the top edge — joint #2.

** Reading the gauge into Emacs
Two ways to get the MAX17048's % onto the screen; start with the first:

1. *Userspace read (recommended for emacsos).* A tiny poller reads the SOC
   register (0x04) over I²C — a few lines of Python =smbus= or an =i2cget=
   call — and a modeline element in elisp shows the %. Full control, no
   kernel/overlay fiddling, and it slots into the same server-next-to-
   =assist= pattern already in place.
2. *Kernel driver.* The in-tree =max17040= driver supports the MAX17048 and
   exposes =/sys/class/power_supply/.../capacity=, which =display-battery-mode=
   reads directly. Conceptually cleaner, but on Pi OS you must instantiate
   it (a custom dtoverlay, or =echo max17048 0x36 > .../new_device= at boot),
   so it's more setup than option 1.

** If the Pi ever browns out under load
Sharing the cell is fine; sharing a *5 V converter* is not. If the modem's
bursts ever drop the Pi (undervolt / lightning-bolt), the clean fix is
full isolation: a *second cell + second boost board* so the two rails
share nothing. Avoid a passive USB Y-splitter for the same reason — it
parallels both loads onto one regulated output, re-creating exactly the
shared rail this design avoids.

* Open decisions
- *Battery placement:* flat on the back (thicker, balanced, holds like a
  phone — leaning this way for the first walk) vs. on a short lead in
  pocket/other hand (lighter slab, one more cable to strain-relieve).
- *Antenna routing:* top-edge whip is the default; revisit if cellular
  signal is poor during the first walk.

* Known unknowns
- *Display model is undocumented.* Every doc says "320x240 touchscreen"
  and never names the HAT, chipset (ILI9341? ST7789?), interface
  (SPI/DPI), or touch type (resistive vs capacitive). The =dtoverlay= that
  would name it lives in =/boot/firmware/config.txt= on the device, not in
  this repo. *Action:* on the Pi, =grep -i dtoverlay /boot/firmware/config.txt=
  and record the answer here. Matters for outdoor touch: resistive needs
  firm taps; capacitive dislikes gloves/sweat.
- *Battery % — design resolved, not yet built.* The plan (MAX17048 over
  I²C → Emacs) is in [[*Power & wiring][Power & wiring]]; until it's wired, watch the PowerBoost
  red LED and time-box the first walk. Still unknown: actual *runtime* (Wh
  of the cell ÷ ~5–8 W load), measurable once the gauge is reading.
- *Antenna part* not named; confirm it ships with the HAT and which
  connector before relying on it.
- *Storage (microSD) size* and *enclosure* not documented (no case is the
  point, for now).
