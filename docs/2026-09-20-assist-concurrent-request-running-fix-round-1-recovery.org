#+title: Assist Web concurrent request round-one recovery
#+date: 2026-09-20

* Status

This implementation record corrects the local-review gaps in the recovered D5
implementation.  It keeps the accepted D5 design
=0716675c69ffcc4254ed1a64def8337aa536304dbf4739f830055d71ec303040=:
each durable submission owns its key, state, markers, callback epoch, and Run
identity.  The queue is the only source of truth for canonical submission and
observation.  The retained =--legacy-*= calls are an explicit nonqueue
compatibility boundary for old no-queue buffers; a queue callback cannot enter
them.

The round-one corrections make failed admission restore the exact editable
draft, persist observing and terminal truth before transport cleanup, validate
complete cache records before restore, and construct the exact endpoint body
and idempotency key before committing a user region.  Adoption persists the
destination before retiring its source, re-observes S1 by exact Run, and rebuilds
provisional entries in S1,C1,C2,S2 order.  A retained source draft has a visible
Restore Draft action; established permanent rejection has its own Dismiss
action after redraw and reconciliation.

Re-observation GET and DELETE callbacks now retain entry identity and a
generation/epoch.  A stale or reversed callback is inert.  The original URL
sentinel remains the sole owner of its deferred completion; the entry sentinel
only performs generic disconnect cleanup when there is no original sentinel.
The aggregate =web= surface is true only while a canonical buffer has a live
POST or observer, and is recomputed after cleanup and last-buffer kill.
