* Integrated behavior

EmacsOS pins wvkbd commit
=f2a9c77eb68f2a798d33290cf7645b6b5365ea6b=.  Its ranked recognizer and
candidate strip remain entirely keyboard-owned.  A candidate press highlights
its cell; release in that cell replaces the committed glide word and trailing
Space; release outside dismisses the strip.  Candidate input ownership prevents
the same touch from starting a second keyboard action.  The result retains the
existing one-shot word-plus-Space editing behavior: Backspace retracts the
unit, explicit Space coalesces with its separator, and punctuation replaces the
separator.

An eligible character swipe whose first threshold crossing is predominantly
rightward produces Control-Meta feedback and emits Control plus Alt with the
character on release.  Existing upward Control and downward Meta gestures are
unchanged.  A rightward candidate that continues far enough can still become a
glide through the existing takeover gates, after which the ranked suggestion
flow owns the result.

The directly supervised command remains
=/usr/local/bin/wvkbd-emacsos --mod-swipe -H 300 -L 300=.  There is no Emacs,
network, or phone-server protocol change.  The dictionary, recognition, and
candidate state are local and compiled into the keyboard; the change adds no
network request, telemetry, or persistent learning.

This supersedes the same 2026-09-08 record's =Cross-repository interface=
=--mod-swipe= enumeration only by adding the rightward Control-Meta gesture and
ranked glide result.  The option name and all other process interfaces remain
unchanged.

* Build and deployment boundary

The existing EmacsOS builder requires a clean checkout at the exact revision,
archives that commit, and builds the archive in the digest-pinned Alpine ARM64
container.  It validates the AArch64 executable, bounded compiled dictionary,
benchmark, dependency set, and exact third-party notice.  The existing
side-by-side installer stages digest-bound regular files and activates them
through the durable transaction and verified service restart, retaining its
rollback behavior.

Both benchmark and install commands must set =WVKBD_REPO_DIR= to the accepted
wvkbd worktree.  The install target is phony and rebuilds the source; relying
on a neighboring default checkout would therefore break the exact-source
claim.
