#+title: Selected phone typography
#+date: 2026-10-05

* Requested behavior
Pierre selected Inter for phone UI and prose, paired with JetBrains Mono for
code and fixed-width content. These defaults belong to the PinePhone OpenRC
session. Desktop Assist and the standalone Emacs installer remain separate.
Root preserves the currently installed generic Email and HITL components when
composing and installing this effort. This document does not claim installation
or physical phone testing.

* Fonts and provenance
The product ships the original variable TTF files and their SIL Open Font
License 1.1 texts. It does not use the private =Phone Type 03= / =Phone Code 03=
preview derivatives. The Google Fonts source revision is
=9710da1eacb3be272583c3224dcb70f9da6eadbb=; original URLs and source hashes are
also recorded in =previews/phone-typography/font-manifest.json=.

Both OpenRC install and update transactions snapshot and digest-check the fonts,
licenses and =phone-fonts.conf= with their existing bounded payload. They install
these flat files under =/usr/local/share/emacsos-openrc=. The updater restores
existing bytes or removes newly introduced files if installation fails. The
session applies =FONTCONFIG_FILE= only to Emacs; the external keyboard keeps its
existing configuration and source bytes.

* Startup and layout
The underlying frame/default face is JetBrains Mono 14, retaining a stable
character-column basis. Phone buffer defaults remap prose and UI to Inter.
Code, configuration, terminal and Dired mode hooks select fixed pitch; already
existing code buffers are updated too. The mode line and header line use Inter.
Chat's existing variable-pitch prose and fixed-pitch Markdown code faces remain
in use. Startup checks that both selected font families are actually available
before opening the Emacs server used by the session's readiness probe.

Shared graphical buttons convert their existing cell budgets into pixels,
including horizontal box padding, then fit Inter labels and clickable spacing
to those budgets. Thread-list text uses the same bounded pixel fitter. Prefix
fitting uses logarithmic measurements rather than measuring every shorter title.
The shared behavior is enabled only by phone startup; ordinary desktop Emacs
keeps its current face and button behavior.

* Validation and Root installation recipe
The standalone =tests/test-phone-typography.sh= runs disposable Alpine graphical
Emacs with the product fonts. It checks actual prose and Markdown-code font
selection, code buffers, reapplication, clickable button padding, control rows,
long-title fit and the number of synchronous width measurements. This is X11
fixture evidence, not proof of the phone's PGTK rendering or physical taps.

Root integrates the exact reviewed typography source over the latest installed
phone composition, preserving generic Email/HITL and keyboard bytes. Regenerate
the final composition's =openrc-manifest.sha256= and its embedded installer and
updater hashes, then run the existing manifest and root transaction checks.
Use the existing OpenRC install/update transaction for the actual phone; never
load new product modules into the running Emacs as a substitute for restart.

After installation, compare all five font/config payload files and startup Lisp
against the exact final composition. On the UI account's normal environment,
Fontconfig must resolve Inter and JetBrains Mono to the installed original TTF
files. The service's Emacs process must inherit the selected =FONTCONFIG_FILE=.
Verify a fresh GUI startup has Inter UI/prose and JetBrains Mono code, no wrapped
or clipped control rows at the actual 360 logical pixel screen, and functioning
navigation, native thread list, SMS/call controls, generic Email and approval
controls. Verify the keyboard hash is unchanged and record the exact package,
tree and startup/live proof. Physical UI observations remain Root/Pierre work.
