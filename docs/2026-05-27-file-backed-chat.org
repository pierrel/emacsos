#+title: File-Backed Chat: .assist Files as Durable Conversations on an Emacs Backend
#+date: 2026-05-27

Today a chat is one ephemeral =*chat*= buffer backed by one fixed
server thread (=CONVERSATION_THREAD_ID=); restart loses the visible
transcript, and there's only ever one conversation.  This experiment
makes a chat a *file*: =find-file foo.assist= opens a chat surface, the
conversation persists (a thread id in the file header + the server
checkpoint), and the buffer auto-saves after each turn.  Every
conversation becomes a durable, greppable, version-controllable
artifact, and you can have many.

The reason this is more than "persist the transcript" is the unifying
idea underneath it: *a conversation is a working directory plus a
backend*, and emacs-control becomes just one backend among the set
assist already supports.  v1 builds that unification up front (option B
from the design discussion) — the phone's emacs becomes a real
=deepagents= =BackendProtocol= implementation (the *EmacsBackend*), so
"edit my files" runs through the same machinery assist's cli/web use.

This revision incorporates the design-review team's findings (verified
against the real assist/deepagents source); the load-bearing corrections
are called out inline where they bite.

* Goal

- A =.assist= file is a durable conversation: open it → chat mode;
  SEND streams exactly as today; the file auto-saves after each turn.
- The agent can *edit the files in the =.assist='s directory* — on the
  phone, in place, via elisp — confined to that directory, with *no
  exfiltration path* (see Security).
- Many =.assist= buffers open at once, each its own thread; reopening a
  file the server still remembers resumes the conversation.
- The legacy ephemeral =*chat*= stays exactly as-is — the zero-friction
  scratch — alongside =.assist= for "I want to keep this."

* Scope

*In:*
- A new major mode (=emacos-assist-mode=) for =.assist= files: the chat
  surface (the *refactored* =chat.el= stream engine — see Decision 5),
  with the target buffer no longer hard-coded and a command surface keyed
  on the *mode*.
- File format: a =#+assist_thread: <uuid>= header + the =you>=/=bot>=
  transcript + applied/rollback notes.  Save transcript-only, on
  =you>=-commit and on end/error/abort.  Reopen does NOT re-parse turns
  (Decision 10).
- Client mints a UUID per new file and sends =thread_id= on every =/chat=
  (absent =thread_id= ⇒ the legacy fixed id, so =*chat*= is untouched).
- Server: =/chat= keyed by =thread_id=; a new =/forget {thread_id}=
  endpoint; per-thread checkpoint.  The fixed-id =/clear= is frozen as the
  legacy alias.
- The *EmacsBackend* (in =emacsos-server=): implements deepagents'
  =BackendProtocol= (=read/write/edit/ls/grep/glob=) by driving the
  phone's emacs daemon via =emacsclient=, confined (=virtual_mode=) to the
  =.assist='s working dir, *composed by assist into a =CompositeBackend=*
  with =StateBackend= routing for internal scratch (Decision 9, Security).
- *Two small, generic seams in assist* (companion PR — see Decision 4):
  (a) inject a custom backend; (b) suppress the default internet-capable
  sub-agents.  Neither is emacs-specific.

*Out (called out so they don't sneak in):*
- *Sync-to-server + docker sandbox on the phone.*  Rejected: the Zero 2 W
  (512 MB) can't run docker or the agent, and in-place elisp is far
  simpler.  The docker/local backend stays in the *model* for a future
  desktop variant; the phone uses the EmacsBackend.
- *=#+assist_workdir:= override* — cut from v1 (speculative; complicates
  the confinement root).  Working dir = the file's directory, full stop.
  Roadmap a header override if a real need appears.
- *Replaying a thread from the file transcript* when the server has
  forgotten it (Decision 7) — roadmap.
- *Multiple simultaneous streams.*  One at a time, server-wide, as today.
- *Raw eval / emacs-control folded into the file-chat surface.*  Kept
  separate and gated (Decision 9 + Security).
- *Migrating the legacy =emacsos-phone= conversation / =*chat*=.*  As-is.
- *A desktop/local-host variant* and *privacy/secrets* handling beyond a
  per-repo =.gitignore= for =.assist=.

* Decisions

Numbered.  Push back on any.  Opinionated calls flagged inline.

** 1. A =.assist= file is a conversation; opening it enters =emacos-assist-mode=

=.assist= goes in =auto-mode-alist=; visiting one initializes the chat
surface over the file's content (read the header for the thread id,
mark the existing content read-only, drop a fresh prompt at the end).
Coexists with the ephemeral =*chat*= — that buffer and its code path are
*unchanged*; =.assist= is the durable sibling.  *Naming* (review finding):
the mode is =emacos-assist-mode= (the repo's elisp prefix is =emacos-=,
single-o; bare =assist-mode= would also collide with the upstream =assist=
package the server imports).  The =.assist= extension and =#+assist_=
headers are filenames/in-file text, not Lisp symbols, so they keep the
product name.

** 2. Unify on "conversation = working dir + backend"; emacs-control IS a backend

*Opinionated.*  assist's =Thread= already centers on a =working_dir= + a
backend; emacsos runs the *degenerate* case (fixed scratch dir,
=sandbox_backend=None=, =EMACS_TOOLS= bolted on).  We generalize: the
phone's emacs becomes a real =BackendProtocol= implementation (the
*EmacsBackend*).  Conceptually =eval_elisp= ≈ a backend's =execute= and
=apply_config= ≈ write+reload — *but for v1 the EmacsBackend implements
filesystem methods ONLY* (=read/write/edit/ls/grep/glob=); it does *not*
implement =execute=, and (critically, Decision 9) it extends
=BackendProtocol= and *never* a sandbox protocol.  The
=eval_elisp=/=apply_config= emacs-*control* path stays separate (Decision
9).  One mechanism (phone elisp); a capability policy per conversation.

** 3. In-place via elisp on the phone — no sync, no docker

*Opinionated.*  File ops run by driving the phone's emacs daemon over
=emacsclient= (=insert-file-contents= / =write-region= /
=directory-files= / etc.).  Files never leave the phone; changes are
inherently local.  We rejected sync-to-server + docker because the Zero 2
W can't host docker or the agent, and in-place is dramatically simpler.

*Accepted cost:* command *execution* on the phone is weak (512 MB), so
v1's file-chat is file-*editing*, not build/run — there is no =execute=
tool (which is also the security win, Decision 9).  Each =BackendProtocol=
call is one =emacsclient= round-trip; the contract is *one batched elisp
call per backend method* (one =directory-files= for =ls=, one elisp
match-loop for =grep=) so method granularity doesn't leak into latency.
The fiddly implementation hotspots are =edit='s exact-string-replace and
=read='s line-numbered =cat -n= + offset/limit semantics over elisp — not
the protocol breadth (the six new-named methods suffice; the deprecated
=*_info= forms and async variants need no custom impl).  =grep=/=glob= may
be deferred-to-stub if the phone smoke shows they're slow — =read/write/
edit/ls= cover the stated use case.

** 4. Lives in =emacsos-server=, not assist — but it needs TWO generic assist seams

*Opinionated, and corrected from the first draft.*  The EmacsBackend,
backend selection, =.assist= handling, =/forget=, per-thread keying — all
=emacsos-server= (+ emacsos elisp).  assist must not learn what emacs is.
But unify-first needs assist to accept two things it can't today, and the
review confirmed *both* against the source:

1. *Backend injection.*  =create_agent= builds the backend internally
   (=create_sandbox_composite_backend= when sandboxed, else
   =_create_standard_backend(working_dir)= — agent.py:193-198), always
   producing a =CompositeBackend=.  Add a way to supply the *default*
   backend (e.g. =backend== / =default_backend==) that assist still wraps
   with its =STATEFUL_PATHS= → =StateBackend= routing — NOT "used
   directly" (a raw backend would bypass that routing; Decision 9).
2. *Sub-agent suppression.*  =create_agent= hardcodes
   =subagents=[context_sub, research_sub, critique_sub_agent]=
   (agent.py:212-265); =research_sub= wires =search_internet=/=read_url=
   (agent.py:467).  These are an *egress channel* and there is no
   off-switch today.  The confined file-chat agent needs assist to expose
   a suppression (e.g. =confined=True= or =subagents=None=).

So the companion assist PR is *two small, general seams* (or a single
=confined== flag that does both) — generic, not emacs-specific — through
assist's three-phase workflow.  The first draft's "one small seam" was
wrong; this is the honest scope.

** 5. Many buffers open ⇒ buffer-agnostic engine; one stream at a time

=chat.el='s stream state is *global singletons* today (markers,
=emacos--chat-in-flight=, the timers, the process), and the handlers
hard-code =(get-buffer emacos--chat-buffer-name)=.  The minimal correct
refactor (review finding — *not* full buffer-localization):
- *De-hardcode the target buffer*: the stream engine inserts into "the
  streaming buffer" (tracked in one variable set at SEND), not the
  literal =*chat*=.  This is the load-bearing change and it's small.
- Because concurrency is *one stream at a time server-wide* (the existing
  global =_STREAM_LOCK=, matching assist's web UI), the *in-flight* state
  (process, markers, timers) is genuinely single-tenant and can stay
  global — markers carry their own buffer, so a global marker into buffer
  B works regardless of =current-buffer=.  Only the *persistent* per-file
  identity (=thread_id=, the file) needs to be buffer-local.
- A second SEND while any stream is in flight is refused with a hint
  (today's behavior, now phrased so it reads sensibly when the streaming
  buffer isn't the one on top).

This turns the existing =*chat*= into a degenerate one-buffer client of
the same engine — a clean improvement, not a fork.  (Scope/step-3 say
"refactor," not "port," deliberately.)

** 6. Thread identity: client-minted UUID in a =#+assist_thread:= header; file is a mirror

On the first SEND in a new =.assist= (no header yet) the client mints a
UUID, writes =#+assist_thread: <uuid>= at the top, and *saves the file
before issuing the POST* (so a crash mid-stream can't leave a server
checkpoint with no file pointer — this ties the header-write into the
=you>=-commit save of Decision 10).  =thread_id= is sent on *every*
=/chat=; *absent* =thread_id= ⇒ the legacy =CONVERSATION_THREAD_ID=, so
=*chat*= needs no client change.

*The transcript is a human-readable MIRROR; the server checkpoint is the
agent's real memory.*  Hand-editing the transcript does NOT change what
the agent remembers (file = display, checkpoint = truth); v1 does not
reconcile a hand-edited file back into the checkpoint.

** 7. Resume: server-remembered → continue; server-forgotten → refuse

Reopening a =.assist= whose thread the server still has → resumes (the
checkpoint replays).  Reopening one the server has *forgotten* (wiped,
=/forget='d, different machine) → v1 does NOT reconstruct from the
transcript; SEND is *refused* with a clear note ("server has no memory of
this conversation — start a new chat to continue"), and the file stays a
readable transcript.

*Consequence to be conscious of (review finding):* after an explicit
=/forget=, the =.assist= file is left on disk as a transcript that can no
longer be continued — it permanently refuses until the roadmapped
reconstruct-from-transcript lands.  =/forget= turns a live file into a
read-only artifact; "new chat" means a *new file*, not resuming the
forgotten one.  This is the accepted v1 behavior, not a bug.

** 8. Working dir = the =.assist= file's directory, confined; all =.assist= excluded

Working dir = the directory *containing* the =.assist= file (a phone
path).  No header override in v1 (Scope-Out).  The EmacsBackend roots
every fs op there with =virtual_mode= (=..=-blocking — the confinement
assist's research backend relies on).  *Confinement is enforced
server-side*: every path is validated/normalized against the
=virtual_mode= root *before* any elisp is emitted; the phone side does no
validation and trusts the server's confined absolute path.  Per-
conversation memory (=AGENTS.md=) lives in the working dir → isolated per
file.

*=.assist= files are excluded uniformly* (review finding): the backend
filters *all* =*.assist= paths (not just the file's own) out of =ls=/
=glob=/=grep= results AND refuses =read=/=write=/=edit= on them — so the
agent can neither list, search, read, nor clobber any transcript.

** 9. File-chat tool surface is confined; raw eval stays separate + gated

*Security-critical; see the Security section for the full model.*  Three
properties, each pinned to a concrete mechanism the review verified:
- *No =execute=.*  Guaranteed by a *class invariant*, not a prune:
  deepagents always registers the =execute= tool but filters it out when
  the backend is not a =SandboxBackendProtocol= (filesystem.py:1694-1707).
  So the requirement is: *EmacsBackend extends =BackendProtocol=, never
  =SandboxBackendProtocol=/=BaseSandbox=.*  A pytest pins this.
- *No internet sub-agents.*  The confined file-chat agent is built with
  the sub-agent suppression seam (Decision 4) so =research_sub= (web
  search) isn't reachable, and with *no =extra_tools== (no =eval_elisp=/
  =apply_config=) so the auto-injected general-purpose sub-agent inherits
  nothing network-capable.
- *Internal scratch stays off the phone.*  The EmacsBackend is composed
  into a =CompositeBackend= with =STATEFUL_PATHS= → =StateBackend= routing
  (Decision 4), so summarization's =/conversation_history/…=, evicted
  =/large_tool_results/=, and =question.txt= scratch live in the
  checkpoint (server-side), not written to the user's phone dir.

The emacs-*control* capability (=eval_elisp=/=apply_config= = arbitrary
code on your phone) is NOT part of this surface — it stays the existing,
explicitly-trusted "change my phone" path, gated.

** 10. File format & save lifecycle

Header (=#+assist_thread:=) at the top, then the =you>=/=bot>= transcript
with =[applied]=/=[rollback]= notes; the transient =[status]= bracket is
gone by save time.  Save *transcript-only* — the trailing =\n> = prompt is
reconstructed on open.  Saves are *programmatic* (=write-region=/
=save-buffer= under =inhibit-read-only=) on two events: after =you>= is
committed (with the header, Decision 6) AND after end/error/abort — never
lose a turn.  A programmatic save while you're composing the next prompt
below the marker is transparent (it doesn't touch the editable region).
=emacos-assist-mode= *disables =auto-save-mode=* and *blocks/aborts
=revert-buffer=* while a stream is in flight (a revert would invalidate
the stream markers).

*Reopen does NOT re-parse turns (review finding — dissolves the
delimiter-collision hazard).*  The =you>=/=bot>= prefixes are NOT treated
as structural on reload: a =bot>= reply may itself contain a line
starting =you>= or =#+assist_=.  On open we (a) read =#+assist_thread:=
from the *top* line only, (b) mark the entire prior content read-only as
an opaque transcript, (c) append a fresh prompt.  No turn segmentation, so
no in-band delimiter ambiguity.  (Streaming appends new turns at the end;
it never needs to re-segment history.)

** 11. Command surface keys on the mode, not the buffer name

The new branch keys on =(derived-mode-p 'emacos-assist-mode)=; the legacy
=*chat*= branch *stays identity-keyed* (=*chat*= has no major mode today),
and the two coexist in the one =emacos--top-commands= =cond=.  Command
names are distinct to avoid the "New chat" overload: in a =.assist= it's
*New file* (open a new =.assist=; does NOT forget the current thread) and
*Forget this chat* (the =/forget= wipe) — separate commands.  ROLLBACK
only appears where an apply can happen (the emacs-control path); the
confined file-chat surface has no =apply_config=, so *no ROLLBACK button*
there — though =[applied]=/=[rollback]= *notes* still render if present in
a transcript (this is the one place "keep rollback notes" and "no rollback
action" coexist; called out so it's not a surprise).

** 12. Editing while streaming = the existing marker design, buffer-agnostic

Tokens insert at a marker *above* the prompt; your draft input lives
*below* it; =save-excursion= preserves your point — already how =*chat*=
works.  With the engine de-hardcoded (Decision 5) this works in whichever
=.assist= is streaming, while you compose your next prompt.  No new
streaming model.

* Security: blocking exfiltration without a sandbox

The docker sandbox blocks exfiltration by giving the container *no
network*.  That method does NOT port: elisp on the phone is a full Lisp
and cannot be network-isolated from inside its own process.  So we flip
from *containment* to *capability minimization* — and the review pinned
each guarantee to a concrete, framework-enforced mechanism rather than
hand-waving "prune the tools":

1. *No code execution.*  =execute= is auto-filtered by deepagents whenever
   the backend is not a sandbox.  *Invariant: the EmacsBackend extends
   =BackendProtocol=, never =SandboxBackendProtocol=.*  Pinned by a pytest;
   if a future change makes it a sandbox to gain =execute=, this control
   silently dies, so the test is load-bearing.
2. *No network / no internet sub-agents.*  Built with assist's sub-agent
   suppression seam (no =research_sub= web search) and no =extra_tools=,
   so nothing in the agent's reach can open a socket.
3. *Confined filesystem.*  =read/write/edit/ls/grep/glob= only, rooted and
   =..=-blocked at the working dir (=virtual_mode=), enforced server-side
   before any elisp is emitted; all =*.assist= excluded uniformly.
4. *Internal scratch routed to state, not the phone* (the =CompositeBackend=
   + =STATEFUL_PATHS= routing of Decision 4/9).

With no egress-capable tool and confined fs, the only outputs are files
*inside the working dir* (your own phone) and the chat reply (back to
you).  That's the equivalent of the sandbox's no-network guarantee,
achieved by tool-surface minimization + a class invariant.

*Residual risk (clear-eyed):* a prompt-injected agent can still write
*bad changes to files in your own working dir* (corruption, or planting a
file you later run yourself).  That's not exfiltration; the control is
*you reviewing the diffs* — which the file-backed, git-friendly working
dir makes easy — not the backend.

* Implementation sequence

0. *(companion, assist)* The two generic seams: inject a default backend
   (assist still wraps it with =STATEFUL_PATHS= routing) + suppress the
   default sub-agents (a =confined== flag is the simplest single API for
   both).  Small PR through assist's three-phase workflow; emacsos depends
   on it merging first.
1. *Server thread keying.*  =ChatRequest= gains =thread_id: Optional[str]=
   (absent ⇒ legacy =CONVERSATION_THREAD_ID=); checkpointer + working dir +
   =THREAD_QUEUE= key by it; =_STREAM_LOCK= stays the server-wide single-
   stream gate (independent of thread id — note so a later refactor doesn't
   drop it).  Add =/forget {thread_id}= (the generalized
   =_clear_conversation=); freeze =/clear= as the legacy fixed-id alias.
   =_build_thread= must NOT =makedirs= a phone path on the EmacsBackend
   path (working-dir existence is the phone's concern).
2. *EmacsBackend (=emacsos-server=).*  Implement the six =BackendProtocol=
   methods over =emacsclient= (one batched elisp call each), =virtual_mode=
   root + server-side path confinement, uniform =*.assist= exclusion,
   =execute= unimplemented, =BackendProtocol= (not sandbox) base class.
   =_build_thread= for a file-chat turn: inject this backend (assist
   composes it), pass the confined flag, no =extra_tools=.
3. *=emacos-assist-mode= (emacsos elisp).*  Refactor =chat.el='s engine
   buffer-agnostic (de-hardcode the target buffer; persistent identity
   buffer-local; in-flight state stays global under the lock); header
   read/write; the save lifecycle + reopen-without-reparse (Decision 10);
   command surface keyed on the mode (Decision 11); auto-save off +
   revert-guard.
4. *Forget command* (=Forget this chat=) + the step-1 endpoint.
5. *Tests + smoke* (below).
6. *PR(s).*  One emacsos PR; the assist seams as its companion (merges
   first).

* Tests / validation boundary

- *ERT:* =emacos-assist-mode= buffer-agnostic engine (token routes to the
  right buffer); header read/write round-trip; reopen-without-reparse
  (a transcript containing a literal =you>= body line round-trips intact);
  save-on-events; command-surface-keys-on-mode (both branches coexist);
  editing-while-streaming markers; revert-guard while in flight.
- *pytest:* =/chat= =thread_id= keying (+ absent ⇒ legacy id); =/forget=;
  *EmacsBackend confinement* (=virtual_mode= rejects =..=; all =*.assist=
  refused/filtered uniformly across read/write/edit/ls/glob/grep); the
  *class invariant* (EmacsBackend is not a =SandboxBackendProtocol= ⇒
  =execute= absent); the confined agent has no internet sub-agent /
  network tool; =STATEFUL_PATHS= route to =StateBackend=, not the phone.
- *smoke:* a round-trip =.assist= turn against the dockerized phone — file
  written with header + transcript, then a resume reads it back.
- *Real phone:* actual file edits in a directory; multiple open buffers;
  streaming-while-editing.
- emacsos has *no small-model eval harness* — validation is tests + smoke
  + live phone.

* Open questions

1. *=working_dir= vs. =workspace_dir= vs. checkpoint.*  With
   =sandbox_backend=None=, assist derives =workspace_dir = "/"= and thus
   =memories_path = "/AGENTS.md"= (agent.py:186-191) — *not* from
   =working_dir=.  Confirm the EmacsBackend's =virtual_mode= root makes
   =/AGENTS.md= resolve to the working dir on the phone (the intended
   confinement anchor), and that the server-side =working_dir= param isn't
   =makedirs='d as a local path.  Resolve in step 2.
2. *=emacsclient= round-trip latency* for the per-turn backend reads
   (=SmallModelMemoryMiddleware= reads =AGENTS.md= through the backend
   *every turn*; =SmallModelSkillsMiddleware= scans sources) plus
   =grep=/=glob= over a dir.  Measure on the phone; the batched-elisp
   contract (Decision 3) is the mitigation; consider deferring =grep=/=glob=.
3. *Exact shape of the assist =confined== seam* — one flag vs. two params
   (=backend== + =subagents==).  Decided in the assist PR's own design
   phase; this doc only requires that both capabilities exist.
4. *Multi-buffer + one global lock UX* — confirm the refuse-second-SEND
   message reads sensibly when the streaming buffer isn't on top.

* Out of scope, next experiments

1. *Replay/reconstruct a thread from the file transcript* — lifts Decision
   7's refusal; lets a =.assist= resume even if the server forgot it.
2. *Desktop/local-host variant* with the docker/local backend — the model
   already accommodates it; the phone simply uses the EmacsBackend.
3. *=#+assist_workdir:= override* — a header to point a chat at a different
   working dir (cut from v1).
4. *Multiple simultaneous streams* (per-thread, beyond the global lock).
5. *Folding emacs-control into the file-chat surface* — kept separate for
   safety; revisit only with a real containment story.
6. *Migrating the legacy =emacsos-phone= conversation* into a =.assist=.
