* Result

Implementation successor =6e230dfe23f2d6cc203a52d0e36149df347fac2f=,
tree =0a7600e49e594654d31651954b3e5478e6f74e0d=, captures a dedicated
per-entry cancellation generation with the exact Run identity when it issues
DELETE.  A confirmed =200/cancelled= receipt no longer compares the
pre-Abort observer epoch: it retires any current stream for that resident
entry, invalidates reobservation, and only then records the terminal state and
starts reconciliation.  DELETE errors and unconfirmed outcomes retain their
Refresh retry behavior.

New entries initialize their handshake field, so starting the real replacement
observer cannot make a plist copy that is detached from its resident queue
entry.  The regression now executes Abort, Refresh GET2, a =running= GET2
callback that calls the actual observation start and advances the observer
epoch, then the earlier confirmed DELETE.  It proves the revived stream is
retired, the entry becomes terminal and reconciles, and the late observer
callback is inert.
