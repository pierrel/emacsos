* 0. Decisions — RESOLVED (Pierre, review round 2)

The three forks this design left open are now settled by Pierre's review. Recorded
here as resolutions (not open questions); §1/§4/§5/§10 are updated to match.

** D1. Client architecture — RESOLVED: shared harness services; voice is a separate thin client
*Not* execution inside the web request path or ownership by the web client.
Pierre's steer (PR review + inline FB §1): "keep the voice client as a separate
client process, parallel to Web/CLI, not embedded in =manage.web=; move generic
client functionality into a shared layer *above* the clients" / "move this one
layer back so it can be re-used between a new voice client and the existing web
client" / "a reasonable cut point is a new 'API' client used by web and voice."

Resolution, updated for authoritative assist PR #213:
1. *Reuse the shared durable Run service and observer seam already in the harness.*
   The web and voice clients consume the same persisted ordinary-turn lifecycle;
   thread catalog (§3) and receptionist orchestration (§4) remain reusable services.
   No parallel =assist.session= facade or second routing implementation is needed.
2. *The web client moved onto durable Runs first and baked there.* Voice becomes the
   second consumer only after that de-risking milestone.
3. *The voice client is a separate thin client* over that API (parallel to web/CLI),
   owning only voice-specific concerns (bridge, VAD/endpoint/barge-in/DTMF, STT/TTS,
   the audio state machine).
4. *Process topology is a deferred, reversible detail, NOT the decision.* Pierre:
   "this does not mean we need two (or more) processes — I'm not suggesting multiple
   processes explicitly." So the shared services form an *internal library boundary*; the
   voice client may be a module in the same uvicorn process or its own process — a
   later, reversible call (default: same process unless a reason emerges). This
   dissolves the old "in-process vs external-HTTP" fork entirely: the layering, not
   the topology, is the point, and a co-located client calls the API directly (no new
   public HTTP surface, no polling latency).
5. *Long-term ownership is documented per component* (§1 ownership table, Pierre's
   "document long-term ownership, not merely where it initially lands"), and the
   EmacsOS-client / shared-service / Assist-harness placement is re-evaluated for every
   responsibility (§1).

** D2. Unknown callers — RESOLVED: do not answer; fail fast, release resources
Pierre: "unknown callers should fail fast and release resources as quickly as
possible." So: *no =ATA=* for a non-allowlisted caller — let it ring out (the
existing =phone-call.el= human screen still lets him pick up manually). No connected
call, no pre-auth answer cost, no decline clip, no modem-occupancy window, minimal
liveness signal to a scanner. (Voicemail is already out of scope per the PRD, so
there was never a product reason to speak to strangers.) §5/§8 updated: DECLINE
becomes DO-NOT-ANSWER with zero detectors and immediate release.

** D3. "Go back" to the receptionist — RESOLVED: BOTH DTMF =*= and an agent tool
Pierre: "support *both* a deterministic DTMF escape (=*=) and an agent-invoked
'return to receptionist' tool. The DTMF path is the reliability guarantee; the
agent path preserves conversational UX."
- *DTMF =*= in IN_THREAD → ROUTER* is the reliability floor: reuses the Goertzel
  detector, cannot false-fire, no model, no eval.
- *=back_to_receptionist()= tool*, merged via =extra_tools= on the in-thread agent
  (§4 — the clean shape; not a =voice=True= boolean), gives the natural spoken
  "take me back." It *does* need a false-fire eval case (the small model can misfire
  it) — accepted as the cost of conversational UX, with DTMF as the guaranteed
  fallback when it misfires.

* 1. Architecture overview

** The layering (Pierre's steer, §0/D1): one shared Run service, thin clients
Voice does *not* execute inside =manage.web='s request path. Instead:
- *The durable Run service shipped by assist PR #213 is authoritative.* Every
  accepted ordinary turn is committed before dispatch and then executed by Run id;
  its queueing, interjection, pause, and recovery semantics are shared by every
  client. Voice reuses that path rather than extracting a parallel =assist.session=
  API or reviving the removed =submit_turn=/journal split.
- *The web client already runs on this service*; voice layers on the baked path.
- *The voice client is a thin client* over the same API, owning only voice-specific
  concerns.
- *Topology is deferred and reversible* (§0/D1.4): the API is an internal library
  boundary; the voice client defaults to a module in the same uvicorn process
  (so it reaches the API by direct call — no new public HTTP surface, no polling
  latency), and may be split to its own process later if a reason emerges. The old
  "in-process vs external-HTTP" fork is therefore moot — it was a false choice
  created by *not* having the shared boundary.

Because the boundary is now explicit, the earlier "in-process is forced by latency /
private hooks" argument is *retired*: a co-located client gets durable turn execution
and the observer hook directly, and a
future out-of-process client would get a deliberately-designed API rather than the
web app's Form→303→HTML accident. The residual cross-process llama-slot contention
(an emacsos phone-chat turn vs a call turn) is pre-existing, unchanged, single-user,
named.

The speech models load *in the session host*, independently and lazily on their
first respective off-event-loop consumer — no separate process, venv, or
=SPEECH_URL= (review consensus: silero already lands here, so exiling only

crash-isolation benefit). STT runs synchronously on the session loop. Blocking TTS
generation runs on a serialized per-call producer so the session keeps draining
inbound PCM and can detect barge-in while Piper synthesizes.

* 2. The PCM bridge (phone-side, hardware-gated core)

*New file: emacsos =server/callbridge/bridge.py=* — one single-file daemon
(=sms_forward.py= mold), non-root (=dialout= group; everything is AT — =ATA=,
=AT+CHUP=, =AT+CLCC=, =AT+CPCMREG=, gain commands — no =mmcli=, no sudo). Deps:
=pyserial=, =websockets=, =dbus-fast= (pure-python).

*Decision 3 amendment (PRD flag #2), endorsed by review:* the bridge is a *dumb,
deterministic pump*; VAD/endpointing/barge-in/DTMF move to the server flow engine.
Reasons that survived review: (a) the hard part lives in one fixture-testable,
tunable place; (b) barge-in reaction via a =flush_uplink= command is one LAN RTT;
(c) the layering principle *holds* — VAD is interpretation, not a deterministic
primitive, so it belongs server-side. (The architect's "silero too heavy for the
Pi" leg was *dropped* — the PRD records on-Pi whisper/piper as feasible and silero
is lighter; the amendment stands on the other legs.)

Internal structure (all one file):
- =AtPort= — opens ttyUSB3 exclusive (=TIOCEXCL=) for the call's duration only;
  released at hangup so =phone-call.el='s per-call open/close human path coexists.
- =PcmPump= — the load-bearing invariant, *balanced by construction*: one thread,
  blocking-read one 20 ms chunk (640 B) from ttyUSB4, then immediately write one
  same-size chunk from =JitterBuffer.pop() or SILENCE=. *The modem read is the
  clock*; the pump never sleeps on a timer, so read/write cannot diverge. Barge-in's
  "clean swap without desync" therefore dissolves: TTS→silence is just the buffer
  clearing; the write cadence never changes.
- =JitterBuffer= — TTS PCM from the WS, target depth ~240 ms, underrun → silence,
  =flush_uplink= → clear. Holds one local canned "lost my connection" clip to play +
  hang up if the WS dies mid-call (>5 s).
- =RingWatcher= — dbus-fast =Voice.CallAdded=, reads =Direction=/=Number=, forwards
  =ring{call_id, caller}=, answers *only* on the server's =answer=. *Second inbound
  while a session is active → the bridge =CHUP='s it and never round-trips the
  server* (single-session enforced where the modem is owned — threat-model #6).
  Server unreachable at ring ⇒ do nothing (the human incoming screen still works).
- =WsLink= — =websockets= client to =ASSIST_VOICE_URL=; shared-secret header; a
  dedicated sender thread drains an outbound queue so a WS stall never blocks the
  pump (drop-oldest downlink under backpressure).

** Wire protocol (phone ↔ server WS)
- Connection: *per-call*, opened by the bridge at =ring=, closed at =call_end= +
  grace. The bridge mints =call_id= (monotonic phone-local counter + boot id).
  Unknown text-frame types are *ignored on both sides* (two-repo deploy skew
  insurance). Binary frames arriving before =answered= or after =call_end= are
  *discarded*.
- phone→server text: =ring{call_id,caller}=, =answered{call_id}=, =call_end{cause}=,
  =dtmf{digit}= (only if the URC path is used — see §5), =stats{rate_hz,underruns}=.
- server→phone text: =answer=, =hangup=, =flush_uplink=.
- binary: raw s16le 16 kHz mono; phone→server = downlink (continuous once
  =CPCMREG=1=), server→phone = TTS. Bound to the call by the connection.

*Transport security (threat-model #4):* the =dtmf= frames carry the PIN
digit-by-digit, and the PCM carries the caller's voice — so the WS *must* be WSS or
enforced WG-only-encrypted end-to-end. Plain =ws://= on the LAN is forbidden; the
deploy gate (§8) states this.

*Clock calibration:* measured modem rate is ~16.7 kHz, not 16.000; TTS at 16 kHz
consumed at 16.7 kHz plays ~4 % fast. =speech.py= always emits protocol-rate 16 kHz.
P3 uses =stats.rate_hz= to calibrate downstream bridge/session playback; the speech
API does not encode the unverified hardware estimate.

*Fake for everything above the bridge:* the modem side is one interface
(=ModemAudio.read_chunk()/write_chunk()= + =AtPort=); =FakeModem= plays WAV fixtures
at a wall-clocked 16.7 kHz and records uplink writes. Additionally, assist gets
=tests/voice/fake_bridge.py= — a WS *client* speaking the whole protocol from
scripted WAVs — so the entire server stack runs end-to-end with zero hardware.
(These two fakes are *not* redundant: different repos, different subjects — the
pump's balanced-write invariant vs. the whole server stack. They share the WAV
corpus.)

*Deploy (Pierre FB — one command, not many):* the call-bridge deploy
(=deploy/call-bridge.service.in= + the udev rule) is a *dependency of the phone's
top-level =make phone-install= / deploy target*, and the server-side voice bits
(route registration, STT/TTS model provisioning) fold into assist's existing
=make deploy= chain — *never a separate command to remember*. A single
=make deploy= (assist) + =make phone-install= (emacsos) brings up everything;
=deploy-call-bridge= exists only as an internal sub-target the top-level one calls
(the =deploy-searxng= "folded into the deploy chain" precedent). ttyUSB3 udev rule
shipped; ttyUSB4 needs none.

*phone-call.el:* unchanged. When the bridge answers first, the existing
=StateChanged= → 4 handler flips the UI to the in-progress screen with Hang-up —
Pierre's escape hatch over an assistant call for free. Residual: a racing human
Accept =ATA='s an active call → modem =ERROR= → harmless.

* 3. Thread-catalog API (Decision 2)

*New file: assist =assist/catalog.py=* (~100 lines, read-only, no model calls, no
=Thread= construction):
- =@dataclass CatalogEntry: id, description, status, updated_at, urgent: bool=
  (=urgent= added per clean-interfaces #4 — the receptionist ranks urgent>recent>new
  and can't without it; it's a pure marker-file read in =state.py=).
- =ThreadCatalog(manager: ThreadManager)= (takes the manager — one dir scan, one
  tid-validation path) with =entries() -> list[CatalogEntry]= and
  =get(tid) -> CatalogEntry | None=.
- Lifts the *file-reading halves* of: =ThreadManager.list()='s scan + =.deleted=
  filter + mtime sort; =description.txt= read; =status.json= read; urgent-marker
  read in =state.py=. Missing description → ="New thread"= (never
  generates one — generation needs a model, stays web-side).
- *What moves from =manage/web=:* only the reads. =DESCRIPTION_CACHE=,
  =set_description=, generate-on-miss, status *writes* stay in =state.py=. All *three*
  =description.txt= read sites (=get_cached_description=, =_thread_title=
  cache-miss, and the status path) become thin wrappers over the catalog, so
  web + voice share one surface (clean-interfaces #12).

Contents are unreachable by construction: the module has no checkpoint access, no
message read, no path into =threads.db=.

* 4. Receptionist agent (the router)

*Shipped in P0.5: assist =assist/receptionist.py= +
=assist/templates/receptionist_system.md.j2=.*

- =receptionist_tools(catalog, domains, on_open, on_new) -> list= (the
  =notify_tools= injected-callback mold):
  - =list_threads()= → spoken-shaped lines from =catalog.entries()= (bounded ~20).
  - =open_thread(selector)= → accepts *number | id | description-substring* (the
    small model keeps habitual arg shapes — agentic #6, pinned by the shipped P0.5
    eval); validates against the last listing (session-scoped
    closure state), calls =on_open(tid)=, returns a spoken directive that *names the
    thread* ("Connecting you to the bike-trip thread." — UX #13, the only mis-route
    catch the caller gets).
  - =new_thread(domain, first_message)= → validates =domain= against the injected
    =ASSIST_DOMAINS= labels, calls =on_new(domain, first_message)= which wraps
    =create_thread_with_message= (manage/web) and *returns the new tid* so the
    session can bind (clean-interfaces #5; the PRD's Intersections named this
    surface). Single-domain fixture → docstring says pass it without asking (US-3).
- *Callback contracts (clean-interfaces #5):* =on_open=/=on_new= are synchronous, run
  on the session worker thread; failures (thread deleted between listing and open,
  domain-creation error) are *caught inside the tool* and returned as a spoken
  directive string, never raised into the agent loop.
- *Construction (agentic #3, corrected):* =langchain.agents.create_agent(model,
  tools, middleware=[ModelRetryMiddleware, BadRequestRetryMiddleware,
  EmptyResponseRecoveryMiddleware])= with exactly the 3 tools + an =InMemorySaver=
  scoped to the call. This is the LangChain 1.x prebuilt loop — deliberately *not
  assist's =create_agent=* (=agent.py=, which wraps =create_deep_agent= and would
  make =AgentSpec.tools= additive to a built-in filesystem/execute/task surface,
  carrying content tools). "Physically lacks content tools" is then true by
  construction; a mechanical test asserts the bound tool set is exactly
  ={list_threads, open_thread, new_thread}=. The three middleware are *not* optional
  polish: =EmptyResponseRecovery= exists because the loop terminates on an
  empty/=<think>=-only AIMessage — for voice that's dead air; =ModelRetry= is the
  only retry layer (=ChatOpenAI= is built =max_retries=0=); =BadRequestRetry= covers
  the 400 class. Skills/memory/loop-detection/interjection middleware are rightly
  omitted.
  *Shipped invariant (Pierre, confirmed):* the receptionist is a *vanilla LangChain
  agent* (=langchain.agents.create_agent=), *never* a deepagent
  (=create_deep_agent=). Carry this into the code — a deepagent would drag in the
  filesystem/execute/task surface the router must not have, and the "physically
  lacks content tools" guarantee (§4) depends on the vanilla loop. The P0.5 mechanical
  test asserting the exact 3-tool set is the enforcement.
- *Model (agentic #8):* built via =select_assistant_model(0.1)= so it
  carries =enable_thinking=False= (a thinking router would burn its whole latency
  budget on =<think>= tokens the caller never hears) and the per-phase httpx
  timeouts (a hung first token = unbounded dead air).
- *Prompt (.j2):* you are a receptionist on a phone call; output is *spoken* — short
  sentences, *no lists / markdown / emoji*; yield immediately to expressed intent;
  when the caller is unsure, offer at most 3 relevant threads (urgent > recent >
  new), never the whole list; elicit a domain conversationally for a new thread; you
  cannot see thread contents — if asked, say so and offer to connect.
- *Latency honesty (agentic #4):* a routed pick is *≥2 model calls* (tool call →
  final reply), not "a single short call," plus prompt-cache eviction when the slot
  alternates receptionist/thread contexts — §5's budget reflects this. The router
  turn does *not* acquire =THREAD_QUEUE= (it's not a thread turn), so §7.2's
  interactive preemption can't protect it from a background turn holding the slot;
  the escalation trigger is "receptionist dead-air behind a background turn"
  (observable as =router_enter=→long gap in the call log), addressed by the §5
  silence watchdog in v1.

*Varied "processing" acknowledgement — named follow-up (Pierre FB), whole experience,
post-hardware.* Distinct from the v1 *functional* acks (silence watchdog §5.1, honest
busy-path ack §5.2, backchannel-after-STT §5.6): the moment the agent *understands a
request and starts processing*, it should speak a short, *highly varied, natural*
acknowledgement ("on it", "ok", "let me think about that", …) so the caller never
sits in cold silence at the top of a turn. It must be varied enough not to sound
canned, and it applies *everywhere* — receptionist and in-thread — not just the
router. Not v1: land it once the whole flow runs end-to-end on real hardware (P3
naturalness tuning), because tuning it needs live turn-latency feel. Tracked in §5's
contract and §11.

** Eval suite: =edd/eval/test_receptionist.py=
In-memory =FakeCatalog= + captured =on_open=/=on_new=, the =test_interjection.py=
=_Journal= harness pattern; N=3→5→10. Cases:
1. Pick-by-topic paraphrase → =on_open= right tid, ≤1 clarifying turn.
2. Expressed intent yields immediately → reply names ≤1 other thread.
3. Unsure caller → proactive *small* offer → reply mentions ≤3 of a 12-thread fixture.
4. Ambiguous topic (two matching descriptions) → disambiguating question, then correct open.
5. New thread, multi-domain → domain elicited, =on_new(domain,…)= correct; single-domain → no domain question.
6. Content-leak probe → declines + offers hand-off; mechanical floor: tool surface has no content tool.
7. Anti-telegraphing phrasings (prompts that don't echo the skill wording).
8. *Spoken-output contract (agentic #5):* every reply across all cases passes a
   =no-markdown / no-bullet-list / ≤N-chars= mechanical filter. Because an eval pass
   rate <100 % still leaks to the caller's ear, the session *also* runs a
   strip-or-reject guard on any reply before TTS.

* 5. Conversation-flow engine + state machine (server-side)

*New files: assist =manage/voice/flow.py=, =manage/voice/session.py=,
=manage/voice/wire.py=, =manage/voice/speech.py=* (3–4 modules — =calllog= folds into
=session.py=; =speech.py= is the in-proc whisper/piper wrapper). Route registered on
the existing =app= via lifespan.

** flow.py — hermetic frame-in / event-out engine (clean-interfaces #9)
Contract: consumes 20 ms PCM frames, emits events; *no web imports, no network, no
threads, no wall clock* (time is derived from frame count — this is what makes
fixture tests deterministic); the *only* I/O is loading the silero onnx model at
construction.
- *VAD: silero-vad* (onnxruntime CPU) over webrtcvad — US-7 (prompt-vs-noise) is the
  stated hard requirement and webrtcvad's GMM detector is the trigger-happy one;
  server placement makes silero's cost irrelevant. (No =SpeechDetector= abstraction
  — one implementation, no contracted second; swap by editing the call site if
  silero underperforms — simplicity #5.) whisper's =vad_filter= stays on
  independently (transcription hygiene).
- *Endpointing:* utterance opens at VAD-speech ≥ 200 ms; closes at trailing silence
  ≥ 700 ms (tunable 500–800) or max-utterance 30 s; emits =utterance(pcm, dur)=.
- *Noise rejection:* two-stage — VAD energy floor here, then STT
  =no_speech_prob > 0.6= / empty-text discard at the session.
- *Barge-in:* VAD-open while state=SPEAKING → emit =barge_in=. Guard against
  TTS-echo false triggers: raised VAD threshold + ≥300 ms sustained speech while
  SPEAKING (echo behavior is a P3 tuning item — a fast "stop!" may not clear the
  guard; named).
- *DTMF: in-band Goertzel here* (8 tone freqs, twist/duration checks). This *inverts*
  the PRD "DTMF on the SIM7600" open question into a by-construction, testable-today
  answer; the modem-URC detector becomes the hardware-gated *upgrade* if AMR mangles
  in-band tones (named risk). Both sit behind =DtmfDetector= (the one interface the
  PRD explicitly mandates as swappable).

*Barge-in semantics (Pierre FB — start simple, tune for naturalness):* the mechanism
can be *very* simple to start, and its rule is precise —
1. The caller starts speaking while the agent is SPEAKING → *stop the TTS
   immediately* (§5.7: invalidate/purge its audio generation and prioritize
   =flush_uplink=) so he isn't talked
   over.
2. *Let him finish* — capture the full utterance (normal endpointing); do not
   cut in.
3. *Do NOT necessarily cancel the in-flight work.* Barge-in stops the *speaking*,
   not the running *turn/subagent*. The captured utterance is delivered as a #199
   *interjection*: the running turn sees it at its next model boundary and decides
   (incorporate / redirect / continue) — exactly the shipped interjection behavior,
   never a hard kill. (Only an explicit "stop" from the caller ends work — and even
   that is the model's decision inside the interjection, not a mechanical cancel.)
4. *Acknowledge when ready and fold into a new turn* — the interjection path already
   does this.
This reuses the interjection mechanism end-to-end (no parallel voice mechanism, per
Pierre's reuse rule). It is explicitly a *feel* problem: expect to iterate the VAD
threshold, the sustained-speech guard, and the "let him finish vs. quick correction"
timing a lot on live hardware (P3). Named as an early real-world-testing watch item
(§11).

** session.py — per-call =VoiceSession=, the state machine
One call at a time (one modem). *Threading (agentic #2):* the async WS receive/send
tasks shuttle frames through bounded closeable inbound/outbound buffers (outbound is
also generation-aware), but every buffer operation crosses through =run_in_threadpool=. Thus
no queue mutex, file I/O, or model call runs on the event-loop thread. One outbound
=get= may be in flight off-loop; that is the one frame allowed by the §5.7 residual
bound. Inbound =close()= and outbound =abort()= atomically mark closed, discard
call-local backlog, and wake every blocked waiter. Graceful outbound
=close(final=hangup)= instead replaces ordinary backlog with exactly one priority
terminal control, keeps it retrievable until the sender takes it, then reports closed
to later gets. The WS owner gives terminal send/socket close a 2 s grace; timeout or
send failure falls through to =abort()= and releases the one-call slot. An abrupt
disconnect/failure also uses =abort()=. Every teardown selects one idempotent path because
coroutine cancellation alone cannot stop an already-running worker call. The session
*loop* thread runs STT + commits Runs and
stays free during THINKING; each *turn* runs on a dedicated turn-runner thread — so a
caller steering mid-turn ("no, the other one") produces an utterance the session can
commit *while its own turn is still running*, and =InterjectionMiddleware.before_model=
delivers it at the next model boundary. Without the split, the one blocked thread
can't accept its own mid-turn steering.

Per-turn audio sub-machine (in ROUTER and IN_THREAD):
=LISTENING → CAPTURING → THINKING → SPEAKING → LISTENING=, with
=SPEAKING --barge_in--> CAPTURING=.

*Go-back to receptionist — BOTH mechanisms (§0/D3, resolved):*
- *DTMF =*= in IN_THREAD → ROUTER* is the *reliability floor*: the Goertzel detector
  (already running for the PIN), deterministic, cannot false-fire, no model, no eval.
  It closes the bound session and re-enters ROUTER.
- *=back_to_receptionist()= tool* on the in-thread agent gives the *conversational*
  "take me back" — added via =extra_tools: tuple= merged into the thread agent's
  spec (the clean shape; *not* a =voice=True= boolean, which can't carry the session
  closure). When the model calls it, the session closes the tid and re-enters ROUTER,
  same as DTMF. It gets a *false-fire eval case* (=test_receptionist.py=-style, on the
  in-thread agent) — the accepted cost of the natural path; DTMF is the guaranteed
  fallback whenever the model misfires or the caller doesn't want to talk.

*Detector scoping by state (threat-model #3 — "no STT pre-auth" made precise):*
- DO-NOT-ANSWER / PIN_FAIL: *zero STT detectors instantiated* — no VAD, no capture, no
  STT ever touches stranger audio.
- GREETING_PIN: *only the DTMF detector runs*; the VAD→utterance→STT path is disabled
  until ROUTER. (In-band Goertzel *does* process pre-auth PCM — it's fixed-function
  DSP, bounded, no model; the honest claim is "no *model/STT* pre-auth," recorded in §8.)

** Turn execution in IN_THREAD (agentic #1, clean-interfaces #2 — durable Runs)
Do *not* re-derive dispatch. PR #213 replaced the old busy/paused/idle helper and
=MESSAGE_BACKLOG= journal with durable Runs. Voice commits each accepted ordinary
turn through =_create_run= before queueing it, carries only the Run id across its
turn-runner boundary, and calls =_execute_run= there. The shared service therefore
owns admission, user-priority FIFO, interjection consumption, pause, terminal state,
and crash recovery. Voice must not recreate =submit_turn= or call =_process_message=
directly.

- Utterance → =Speech.transcribe()= (in-proc) → text → committed ordinary Run. The
  terminal observer is the only source of reply delivery for both immediately
  runnable and queued turns.

** The conversational contract (UX lens — audio plumbing is not enough)
The design specifies *who speaks first at each state entry, what bounds every
silence, and what each acknowledgment honestly means*:
1. *Silence watchdog (UX #1, BLOCKER):* whenever state is THINKING or waiting on the
   queue/slot and no audio has been enqueued for ~6–8 s, play a rotating canned
   progress clip ("still with me — working on it"). One mechanism covers the three
   dead-air cases: a queued Run (minutes to next superstep), cold prefill on
   a big thread, and a cross-process web/chat turn holding the llama slot.
2. *Honest busy-path ack (UX #2):* when the committed Run waits behind active work, immediately speak
   a canned *honest* line ("It's still working — I've noted that, I'll pick it up the
   moment it wraps"), *not* the "mm-hm" backchannel (a misleading ack is worse than
   silence).
3. *Auth-ok + first speaker (UX #3):* play a canned "You're in — one sec" at
   =auth_ok= while the router's first (orienting) turn generates; the .j2 makes the
   router *open by orienting* ("you've got the bike-trip thread and two others
   working — what do you need?"). This is the shipped-approval-nobody-could-find
   failure mode; the state change must be audible where the caller is.
4. *PIN completion + correction (UX #4):* fixed-length PIN; =*= clears and restarts
   (no strike); inter-digit timeout ~5 s → one re-prompt then strike; distinct clips
   for wrong-PIN vs final-strike; DTMF type-ahead over the greeting supported (the
   caller will punch without listening).
5. *Owner lockout recovery (UX #5):* the only person who ever hits the gate is
   Pierre; the final-strike clip *states the recovery* ("three tries — call back in a
   minute"); short cooldown for the (former) allowlist path; the lockout surfaces as
   a web-UI event so he can see what happened.
6. *Backchannel after STT (UX #6):* play the thinking backchannel only *after* STT
   accepts (endpoint + ~300 ms STT still beats 1.5 s), so a =no_speech_prob=-discarded
   utterance never gets a false ack; on discard-after-listen, speak "sorry, say that
   again?".
7. *Invalidate TTS at the flush boundary (UX #7):* the producer splits sentence
   results into 20 ms PCM frames carrying a TTS generation. A bounded outbound buffer
   owns one serialized accept/invalidate boundary. Producer backpressure waits on a
   condition that releases its lock and rechecks generation on wake. On =barge_in=,
   one nonblocking buffer operation invalidates the generation, purges its queued
   frames, and inserts =flush_uplink= at the front, without waiting for Piper or
   capacity. Later old-generation frames are rejected; only a frame the WS shuttle
   already dequeued can escape. Residual audio = ~300 ms guard + one 20 ms frame + RTT.
8. *"Next safe boundary" defined (UX #8):* a spoken async interjection lands only when
   state == LISTENING and VAD-silent ≥ ~1.5 s and no turn in flight — *never* during
   CAPTURING or SPEAKING (the agent must not interrupt *him*); queued behind the
   current reply.
9. *Async delivery in ROUTER (UX #11):* if a child task's durable parent wake completes while the caller
   is at the receptionist (bound to no tid), *do not* silently downgrade to an
   invisible web badge — the receptionist mentions it at the next safe boundary
   ("the research in the trip thread just finished — want to hear it?"). US-5's
   promise is "speaks the result if I'm still on."
10. *Hand-off names the thread* (UX #13, in =open_thread='s directive).
11. *Backchannel variety* (UX #15): vary by context (question → "let me check";
    statement → "mm-hm"; sub-second turn → silence); count the 240 ms jitter-buffer
    fill in the first-audio budget (~540 ms perceived — within 1.5 s).

*wire.py:* WSS =/call= endpoint — secret-header auth, one concurrent call, frame
codec, per-call queues, the resource caps of §8.
*speech.py:* lazy in-process whisper + Piper, synchronous and called only off the
event loop. STT runs on the session loop; a serialized per-call TTS producer splits
sentence results into generation-tagged 20 ms frames while the session continues
consuming inbound PCM. Token-streaming
TTS is a named post-v1 optimization. Piper output is peak-normalized ~0.9 FS and
resampled to the protocol's 16 kHz (hardware-calibrated rate remains P3).

* 6. Speech (in-process, §0/D1 consensus)

Folded into the session host per review — *not* a separate service/venv/unit:
- STT: faster-whisper =base.en=, CPU, =vad_filter=True=, =condition_on_previous_text=False=,
  optional =initial_prompt= vocab bias; batch per (short, endpointed) utterance —
  streaming STT is complexity v1 doesn't need. Exposes =no_speech_prob= for noise
  rejection.
- TTS: pinned Piper =en_US-lessac-medium= (22.05 kHz native), resampled to the
  protocol's 16 kHz; =Speech= streams sentence chunks and the TTS producer packetizes
  them into 20 ms frames before outbound acceptance.
- Models load independently and lazily on first use, off the event loop: Whisper
  on the session loop and Piper on the serialized per-call TTS producer. If a
  concrete pip resolution conflict with assist's deps materializes at install
  time, split into a process *then* — not speculatively now.

* 7. Harness-side async-subagent capability (PRD reviews #7–9)

*Position after authoritative PR #213:* assist ships asynchronous, user-steerable
subagents as durable child Runs. The main thread receives task identity immediately;
the Run service owns lifecycle, dependency ordering, and recovery; terminal child
work creates a durable parent wake-up. Voice adds no subagent mechanism.

** 7.0 deepagents native async-subagents — reviewed (Pierre FB)
*What it is* (=deepagents.middleware.async_subagents=): a supervisor launches a
background subagent and gets a task id immediately, keeps talking, and later
*steers* it — five tools =start_async_task / check_async_task / update_async_task /
cancel_async_task / list_async_tasks=. It runs via any Agent-Protocol transport
*including in-process (ASGI)* — a remote graph server is *not* required (correcting
this doc's earlier "remote graph server" objection). Available as a preview since
deepagents 0.5.0; assist is on *0.6.1* and both symbols import today — so "upgrade
if we must" resolves to *we already have it*.

*Why the interface is a great fit for voice.* The lifecycle launch → keep-talking →
steer (=update=) → cancel → deliver maps 1:1 onto the call UX: kick off research,
keep the conversation natural, let the caller redirect it ("actually only road
bikes"), cancel on "never mind," speak the result when it lands. That is exactly
what US-5 + barge-in want, and the tool surface is cleaner for the *supervisor's*
view than a hand-rolled one.

*Hardware constraint (honest):*
- *Single slot.* The feature's value is the subagent making progress *concurrently*
  with the main agent. assist has *one* =--parallel 1= llama slot serialized by
  =THREAD_QUEUE=; two agents cannot use the model at once — concurrent dispatch
  serializes or O(T²)-thrashes prefill. Here "async" means the caller and supervisor
  remain interactive while durable work is deferred and serialized.
- *Pull vs push.* The middleware delivers by the supervisor *polling* =check_async_task=;
  voice needs *push* — the turn-completion observer (§7.1) speaking the result the
  instant it's ready. Polling on a live call is dead air.
- *State model.* PR #213 resolved this by representing ordinary and child work as
  durable Runs, with dependency ordering and restart recovery in one service.

** v1 slice (this effort) — the harness pieces, all clients benefit
1. *Turn-completion observer seam* (the one genuinely new hook):
   =register_turn_observer(cb)= in =manage/web/threads.py=, a *list* of observers
   invoked after a turn's terminal bookkeeping and queue release with
   =(tid, stage, origin, reply_text, run_id)=. Contract (clean-interfaces #6):
   per-observer exception isolation (log-and-continue; an observer must never disturb
   terminal state or other observers); called synchronously on the
   turn's worker thread (which varies — anyio pool, =_ResumeScheduler=, or the voice
   turn-runner — so observers must be thread-safe and non-blocking). The voice
   adapter is one registered observer; the badge/unseen path is untouched.
2. *Interactive-class waiters in =THREAD_QUEUE=* — *deferred to P3 / observed need*
   (simplicity #4): a holder already pauses at its next superstep once the 600 s
   quantum expires when any waiter is behind it, and the dominant worst case (a
   multi-minute in-superstep subagent) is untouched by this piece. v1 ships the
   spoken-hold path (via the =on_queue_state= callback =ThreadManager.get= already
   takes) + the §5 silence watchdog; the ~20-line interactive waiter (reusing the
   shipped pause verbatim) is added when a fake-bridge/live call actually exhibits the
   cross-thread wait. It does *not* fix the in-superstep case — stated plainly.
3. *Voice turns run with the standard web spec and durable Run service* — so US-5 is
   inherited with zero voice-specific agent code.

** Delivery adapter (=manage/voice/session.py=)
The observer fires at a turn's terminal exit. It is the adapter's *single* reply
source: voice never also speaks an executor return, so immediately runnable and
queued turns follow the same exactly-once delivery rule. Call live + bound tid →
enqueue for the next safe boundary (§5.8); call ended or
bound elsewhere → thread update + unseen badge (agent may =notify()= if urgent — no
new SMS machinery in v1; US-5's "texts me" is a *named narrowing*, review NIT).

** Shipped async trajectory (PRD #9)
PR #213 completed the assist-wide default flip. Context, research, and critique work
start as durable child Runs and remain steerable through the task lifecycle. Ordinary
user Runs receive dispatch priority when the shared model slot becomes available;
voice inherits that behavior without a voice-only priority or cancellation path.

* 8. Security design

*Honest trust-root (threat-model #7, #9):* the bridge supplies *both* the caller-id
string *and* the DTMF stream, over one WS guarded by one static shared secret, and
assist web binds =0.0.0.0= (configured in =__main__.py=; TLS optional). So the advertised
allowlist→PIN layering collapses to *(WS secret ∧ PIN)*. The doc states this plainly:
the WS secret is an *auth credential, not a reachability convenience*; the caller-id
allowlist is *defense-in-depth for future multi-user*, not a gate against a
secret-holder. Accepted for a single-user home system — *because it is named*.

- *Global PIN lockout (threat-model #1, BLOCKER):* per-caller lockout fails — an
  attacker rotates the (spoofable, bridge-fabricated) caller-id per attempt for
  unlimited 3-strike windows. The lockout is *global*: total PIN failures per rolling
  window across all callers → the line stops offering the PIN prompt for a cooldown.
  PIN is *≥6 digits* (it is the crypto root).
- *Do-not-answer unknowns (threat-model #2 → §0/D2):* pending Pierre's D2 call;
  recommended. Removes the answer cost + the single-modem self-DoS window.
- *Detector scoping (threat-model #3, §5):* "no *model/STT* pre-auth" enforced by
  state — DO-NOT-ANSWER / PIN_FAIL instantiate zero STT detectors; GREETING_PIN runs only
  DTMF.
- *Encrypted transport (threat-model #4):* WSS or WG-only-encrypted mandatory; =dtmf=
  frames are PIN-bearing in transit; plain =ws://= forbidden. *Deploy gate:* the
  =0.0.0.0= bind means "WG-only" depends on a host firewall the deploy must assert (or
  bind the voice route to the WG interface explicitly).
- *WS resource caps, quantified (threat-model #5 — the class the SMS daemon missed):*
  max binary frame size (reject a 1 GB PCM frame → OOM), max control-frame rate
  (=ring=/=dtmf= flood), *exactly one* WS connection, handshake/idle timeout (the
  slowloris analog: connect, send the secret, dribble → holds the single-call slot),
  max session duration 30 min. Accept/handshake stays off the loop thread.
- *Second call rejected at the bridge (threat-model #6, §2):* the bridge owns the
  modem; a second inbound during an active session is =CHUP='d there, no server
  round-trip — no concurrent brute-force channel.
- *Caller-id handling (threat-model #8):* allowlist compare is *exact equality on
  normalized E.164*; the string is =json.dumps=-encoded into =events.jsonl= (no
  log-forging via embedded newlines); length-capped (reject a 10 KB caller-id).
- *Router containment:* by construction (no content tools bound — §4), mechanical
  test.
- *Authz:* PIN ⇒ the single owner; voice turns are =sender=None= owner turns — the
  same backend model as every client (review #11); the interjection sender gate
  composes (verified).
- *Named residuals (must appear, accepted not hidden):* ambient prompt-injection —
  anyone audible in the room post-auth can drive the agent; the noise rejection is a
  *quality* mechanism, not a security boundary (threat-model #11). DTMF replay is an
  accepted property of DTMF-over-telephony (#12). Allowlist-membership oracle (a
  spoofer can enumerate the ~1-entry allowlist) (#10). The bridge-side mirror log
  (§9) is held to the *same* no-digits/no-PCM rule as the server log (#13). Context
  (#14): egress-approval HITL needs the web CSRF token, so a *voice caller cannot
  approve egress* — a containment-by-accident + a UX dead-end to note; and the
  existing web UI has *no PIN at all*, so voice-with-PIN *raises* the owner-access bar
  relative to web, not lowers it.
- *Secrets/config:* =ASSIST_VOICE_PIN_HASH= (salted), =ASSIST_VOICE_ALLOWLIST=,
  =ASSIST_VOICE_SECRET= via =.deploy.env=; no real numbers/PINs tracked (fixtures
  =+1XXX…= / =000000=).

* 11. Risks & open questions

1. *Dead air behind a long superstep* (single slot): the silence watchdog covers the
   caller experience; interactive waiters shorten the between-superstep case when
   observed; the in-superstep case is the named bound with the §7 escalation ladder.
   Accept for v1 — *Pierre confirmed:* acceptable, no v1 UX tweak; but flagged as
   something *real-world testing will surface quickly*, so it's an *early-testing
   watch item*: if live calls hit it often, that is the evidence that triggers the
   ordinary-Run scheduling and/or the interactive waiter.
2. *In-band DTMF through AMR:* may be mangled. Ship Goertzel first (testable now); P3
   probes modem-URC as the swap. If both fail: spoken-digit PIN is *rejected*
   (Decision 1); fallback = allowlist-only + longer cooldowns — flag to Pierre.
3. *TTS echo triggering barge-in:* raised in-SPEAKING thresholds; truth in P3;
   escalation = energy-correlation echo suppression in flow.py.
4. *Modem clock drift* (~16.7 kHz): calibration constant from =bridge_stats=; P3.
5. *Pi pump jitter:* buffer sizing first; =SCHED_FIFO= via =CAP_SYS_NICE= only if
   underruns observed.
6. *WG/wifi drop mid-call:* bridge canned-apology + hangup after 5 s; session marks
   ended; async work unaffected.
7. *Receptionist model quality:* eval-first; the prompt is the knob; N=10 gate before
   P1 integrates it.
8. *One llama slot shared cross-process with emacsos phone-chat:* pre-existing,
   unchanged, named.

* 12. Explicitly rejected alternatives

- *In-process-in-=manage.web= hosting AND external-process-over-new-HTTP-routes* —
  *both* superseded by §0/D1 (Pierre): shared harness services dissolve the fork. A
  co-located client calls them directly (no new HTTP surface); the topology
  is a later reversible detail.
- *Separate speech service / venv / unit* — folded in-process; the dep-isolation
  boundary cut the ML family in half for a theoretical crash-isolation benefit.
- *DTMF-only OR tool-only go-back* — §0/D3 (Pierre) takes *both*: DTMF =*= is the
  deterministic reliability floor, =back_to_receptionist()= (via =extra_tools=) is the
  conversational path with its false-fire eval. Neither alone.
- *=voice=True= flag on =ThreadManager.get=* — the go-back tool is merged via
  =extra_tools: tuple= (the clean shape), not a per-client boolean.
- *=SpeechDetector= abstraction* — one implementation; swap by editing the call site.
- *Voice-specific async-subagent machinery* — unnecessary after PR #213; voice
  consumes the shared durable child-Run lifecycle and push delivery.
- *webrtcvad as primary* — weaker on US-7; not abstracted behind an interface.
- *Phone-side VAD/endpointing (Decision 3 as written)* — splits the hard part across
  two hosts; VAD is interpretation, belongs server-side.
- *Raw-TCP custom framing* — costs hand-rolled framing/keepalive vs one pip dep.
- *Voicemail, outbound, wake word, push-to-talk, speaker-ID, token-streaming TTS* —
  out of scope per PRD (streaming TTS a named post-v1 optimization).
